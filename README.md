用中文問台電機組出力，系統回答 —— 且答案要嘛正確、要嘛誠實說不知道。

## 這個專案在解什麼問題

台電開放資料有一堆「查得出來但答案是錯的」問法。最典型的：

```
問：「台中電廠去年總發電量多少？」
```

一個 naive 的 Text2SQL 會很有自信地 `SUM(台中#1..#10)` 給你一個數字，而那個數字**兩層都錯**：

1. 資料記的是**系統尖峰那一刻的瞬時出力**（萬瓩），不是發電量 —— 把 577 個瞬時功率相加沒有物理意義
2. 台中的 4 台氣渦輪被歸進 `氣渦輪` 殘差欄，跟全系統其他 GT 混在一起拆不出來 —— 總計會少算

所以這個專案的重點不是「讓 LLM 寫出 SQL」，而是**在 SQL 執行前判斷這個問題能不能被誠實回答**。

## 核心設計：雙守門層

| 層 | 管什麼 | 攔下的失敗形態 |
|---|---|---|
| SQL 守門 | SQL 本身安不安全 | 資料被改、被撈走 |
| **語意守門** | 答案有不有效 | **錯得很有自信** |

語意守門有 9 條規則，分三個嚴重度（`refuse` / `disclose` / `clarify`），全部是可機器檢查的
SQL 形狀判斷 —— 不是丟給 LLM 自己想。規則全表見規格附錄 A。

### `taipower_align/` 已完成的部分

把台電兩個開放資料集的發電廠與機組名稱對齊，產出可直接 join 的對照表。

- **A 檔 175 台機組 100% 對應**
- **B 檔 64 欄對到 43 欄（67%）**，剩下 21 欄屬 A 檔範圍外（核能／民營電廠／再生能源彙總）
- 附一份 10 條的資料陷阱清單 —— 這份清單就是語意守門層的規則來源

```bash
cd taipower_align
python align.py    # 產生 crosswalk.csv + crosswalk.txt
python final.py    # 產生 daily_long.csv + final.txt
```

只依賴 Python 標準庫。細節見 [`taipower_align/README.md`](taipower_align/README.md)。
