# 台電發電廠 × 機組名稱對齊

把台電兩個開放資料集的**發電廠與機組名稱對齊**，產出可直接 join 的對照表。

- **A 檔（機組主檔）** — 每列一台機組，含裝置容量、燃料、商轉日期
- **B 檔（每日供需）** — 寬表，每欄一個機組／電廠，記錄每日尖峰時刻出力

兩者命名體系完全不同、粒度也不同，無法直接 join。本專案解決這件事。

**成果：A 檔 175 台機組 100% 對應，B 檔 64 欄對到 43 欄（67%）**，剩下 21 欄屬 A 檔範圍外（核能／民營電廠／再生能源彙總）。

---

## 快速開始

```bash
python align.py    # 產生 crosswalk.csv + crosswalk.txt
python final.py    # 產生 daily_long.csv + final.txt
```

只依賴 Python 標準庫，無需安裝套件。兩支腳本都從資料夾內的 `units.csv` / `daily.csv` 讀取，**資料夾可整包搬移**。

重新抓取原始資料：

```bash
python fetch.py            # 更新 units.csv + daily.csv
python fetch.py --extra    # 另外抓 3 個擴充資料集
```

## 核心問題：三層粒度 + 四套命名

### B 檔的 64 欄混了三種粒度

```
單機      台中#1…台中#10、林口#1-#3、興達#1-#4、大林#1#2
多機彙總   大潭(#1-#9)、通霄(#1-#6、GT#9)、興達(#1-#5)、協和(#1-#4)
分廠彙總   德基、青山、谷關、天輪、馬鞍、明潭、鉅工、大觀、大觀二、離島…
```

不先拆開粒度，不可能對齊。

### 關鍵解法：A 的機組名稱前綴 = B 的分廠欄位名

B 的「德基／青山／谷關／天輪／馬鞍」看起來像五座電廠，其實**全部都是大甲溪發電廠底下的機組群**。A 把這一層藏在機組名稱的前綴裡：

```
A: 大甲溪發電廠 → 德基#1機/德基#2機/德基#3機      →  前綴「德基」 = B 的「德基」欄
                  青山一機/青山二機/青山三機/青山四機  →  前綴「青山」 = B 的「青山」欄
```

同一招適用於明潭（明潭／鉅工／水里）、大觀（大觀一廠→`大觀`、大觀二廠→`大觀二`）、東部（碧海／立霧／龍澗）。

### 命名轉換規則

| 模式 | A 寫法 | B 寫法 | 轉換 |
|---|---|---|---|
| 國字→阿拉伯 | 中一機…中十機 | 台中#1…台中#10 | `中{國字}機` → `台中#{n}` |
| 廠名簡寫 | 林一機 | 林口#1 | 首字縮寫還原 |
| 燃氣複循環 | 興達複一機 | 併入 `興達(#1-#5)` | 前綴含「複」→ 燃氣欄 |
| **燃煤 vs 燃氣同名** | 興三機 / 興達複一機 | `興達#3` / `興達(#1-#5)` | **必須用「複」字區分**，否則兩種機組會混在一起 |
| 離島合併 | 尖山12台＋塔山21台＋珠山4台 | 單一 `離島` 欄 | 37 台壓成 1 欄 |

### 四套命名並存（跨資料集時注意）

同一台機組在台電不同資料集有四種寫法：

| 資料集 | 台中燃煤1號 | 明潭5號 | 南部複循環1號 |
|---|---|---|---|
| `units.csv` (d004011) | 中一機 | 明潭#5機 | 南部複一機 |
| `daily.csv` (d006005) | 台中#1 | 併入 `明潭` | 併入 `南部(#1-#4)` |
| 歲修排程 (d006008) | — | 明潭#5 | — |
| 10分鐘 (d006010) | 台中#1 / 中火 | — | 南部CC#1 |

要接 `d006008` 或 `d006010` 得**再做一次對齊**，本專案尚未涵蓋。

## 對齊方法：用裝置容量客觀驗證

不靠字串相似度，而是拿 **A 的裝置容量 vs B 的全期實測最大值** 對帳（B 單位為萬瓩，A 為瓩，差 10,000 倍）。

```
B欄位             A機組                台   A容量   B實測max   比值
林口#1            林一機                1   80.00    80.30    1.004  ✓
台中#1            中一機                1   55.00    51.70    0.940  ✓
通霄(#1-#6、GT#9)  通霄複一~複六+#GT9    7  395.19   385.70    0.976  ✓
南部(#1-#4)       南部複一~複四機        4  111.78   115.40    1.032  ✓
德基              德基#1~#3機           3   23.40    21.60    0.923  ✓
```

比值落在 **0.80 ~ 1.06** 視為合理；超出範圍的會在 `crosswalk.txt` 標記 `<<< 比值異常`。

**判讀規則：**

- **ratio > 1.06** → 真問題：A 檔缺機組，或對應錯誤
- **ratio < 0.80** → 通常正常：抽蓄／水力／離島本來就不會滿載（見下節）

---

## ⭐ 最重要的語意：B 的數值不是發電量

`daily.csv` 的機組欄位記錄的是**系統尖峰負載那一刻的瞬時出力（萬瓩）**，不是日發電量、不是日均、也不是裝置容量。

驗證方式與結果：

```
各機組欄位加總 ÷ 尖峰負載
  中位數 = 0.969    p10 = 0.939    p90 = 0.997     (400 天樣本)
```

加總幾乎剛好等於尖峰負載。這解釋了所有 ratio < 1 的欄位——**它們都不是對應錯誤**：

| 欄位 | 牌牌 | max | 中位數 | =0 天數 | 判讀 |
|---|---|---|---|---|---|
| 明潭 | 160.2 | 117.6 | 25.4 | 143/577 | 抽蓄，只在尖峰放電 ✓ |
| 大觀二 | 100.0 | 83.1 | 15.5 | 120/577 | 抽蓄 ✓ |
| 離島 | 25.9 | 18.4 | 11.5 | 0/577 | 離島柴油常態部分負載 ✓ |
| **立霧** | 3.2 | 1.5 | 0.0 | **572/577** | **停機**，非對應錯 |

> 立霧為何幾乎全期為 0？`d006008` 歲修排程給了答案：
> `2026 | 水力 | 立霧 | 20250701 | 20260731 | 取水發電修復工程` —— 停機 13 個月。

### 🚫 這些欄位不能加總當發電量用

要算電量必須另抓月報或 `d006010`。把 577 天的尖峰瞬時值相加**沒有物理意義**。

## `crosswalk.csv` 欄位

| 欄位 | 說明 |
|---|---|
| `b_column` | B 檔欄位名（含 `(萬瓩)` 後綴）|
| `a_plant` | 對應電廠，多座以 `\|` 分隔（由實際比對到的機組推導）|
| `n_plants` | 涵蓋幾座電廠 |
| `a_units` | 對應機組清單，以 `\|` 分隔 |
| `n_units` | 機組台數 |
| `cap_a_wankw` | A 檔裝置容量合計（萬瓩）|
| `obs_max_b` | B 檔全期實測最大值（萬瓩）|
| `ratio` | `obs_max_b / cap_a_wankw`，驗證用 |
| `confidence` | 高／中／低 |
| `is_residual` | **1 = 殘差欄位**，成分由消去法決定，定義會隨版本漂移 |
| `is_bucket` | 1 = 桶狀欄位（含 residual 及規則穩定的桶）|
| `note` | 備註 |

### 為什麼分 `is_residual` 和 `is_bucket` 兩個旗標

| 欄位 | is_bucket | is_residual | 理由 |
|---|---|---|---|
| 其他小水力 | 1 | **1** | 定義是「其他」，台電多開一個具名欄它就變小 |
| 氣渦輪 | 1 | **1** | 全系統氣渦輪的殘餘（`ratio 1.34` 就是 A 檔只涵蓋台中 GT 造成的）|
| 離島 | 1 | 0 | **地理定義**（澎湖＋金門＋馬祖），規則穩定不會漂移 |

殘差欄位的定義**會隨其他欄位變動而無聲改變**。哪天台電給曾文一個專屬欄位，`其他小水力` 就從 41.84 變小——欄名一樣、沒有公告、歷史資料不會回填。**跨年度比較時這種欄位會製造假趨勢。**

## 陷阱清單

| # | 問題 | 影響 |
|---|---|---|
| 1 | **B 是尖峰瞬時出力，非發電量** | 加總無意義；ratio<1 屬正常 |
| 2 | **單位差 10,000 倍** | A 是瓩、B 是萬瓩 |
| 3 | **6 座電廠橫跨具名欄位與殘差桶** | 無法還原電廠層級總出力（見下）|
| 4 | 殘差欄位定義會漂移 | 不適合跨期比較 |
| 5 | 燃煤與燃氣機組同名 | `興三機` vs `興達複一機` 須用「複」字區分 |
| 6 | 四套機組命名並存 | 接新資料集要重新對齊 |
| 7 | A 檔「不定期更新」，實際已過期 | 缺 3 處機組（見下）|
| 8 | 退役機組欄位保留為 0 | `WHERE 核三#2 > 0` 在不同期間行為不同 |
| 9 | 中文欄位名 + 全形括號 | 欄名含 `(萬瓩)`、`(#1-#9)`、`、` |
| 10 | `日期` 是 `YYYYMMDD` 字串 | 非日期型別 |

### 陷阱 3 詳解：被拆兩邊的 6 座電廠

| 電廠 | 具名欄位 | 另有機組落在殘差桶 |
|---|---|---|
| **台中** | 台中#1…#10 | GT#1-#4 → `氣渦輪` |
| 大甲溪 | 德基／青山／谷關／天輪／馬鞍 | 后里、社寮、后里示範 |
| 明潭 | 明潭／水里／鉅工 | 濁水、北山、湖山、南岸二 |
| 東部 | 碧海／立霧／龍澗 | 龍溪、清水、銅門… 共 12 台 |
| 萬大 | 萬大 | 松林#1#2 |
| 卓蘭 | 卓蘭 | 景山 |

**台中發電廠最容易踩到**——它的燃煤機組有 10 個獨立欄位，看起來很完整，但 4 台氣渦輪被丟進 `氣渦輪` 桶裡跟全系統其他 GT 混在一起，拆不出來。算「台中發電廠總出力」會少算。
